# Sansa 构建方法拆解与云栖实现方案

## 公开前端可确认的结构

通过公开 HTML、构建产物名称与运行时代码中的公开字符串，可以确认 Sansa 采用了以下结构：

- Vite 负责入口与动态分包，游戏主体延后加载。
- Three.js/WebGL 负责 3D 场景、光照、相机、角色骨骼动画与拾取。
- 场景和角色使用 GLB；材质包含木、石、布、屋顶和地面等 PBR 贴图。
- 远端角色有精简 LOD 模型，并做了实例化、姿态缓存、可见性裁剪等优化。
- WebSocket 承担房间快照和增量事件，包含移动、座位、动作、离开、心跳和断线恢复。
- 房间以 `room / instance / region` 切分，并公开表现为约百人一房。
- 木鱼、念珠、礼拜、合掌、诵经与声音设置是相互独立的体验模块。
- 移动端安全区、Safari 可视视口、降级动画与无障碍状态被单独处理。

这些信息只用于理解工程方法；本项目没有复制目标站的源代码或素材。

## 云栖的一体化方案

### 客户端

- Vite + Three.js。
- 程序化几何取代外部 3D 素材，便于快速迭代和规避版权问题。
- 所有声音由 Web Audio 合成，不依赖第三方音频。
- 角色状态统一为 `{id, name, seat, action, color}`。
- UI 和 WebGL 分层：场景只负责空间，DOM 负责文本、对话框与无障碍。

### 多人层

- 演示版：BroadcastChannel，实现同源多标签页同步。
- 生产版：WebSocket 房间服务，消息分为 `snapshot` 和 `delta`。
- 服务器拥有座位状态的最终决定权。
- 客户端只广播离散动作和低频位置，不同步每一帧动画。

### 产品层

- 没有聊天输入框，保留“弱连接、低社交压力”。
- 空坐垫带微光，满座自然形成现场感。
- 仪式动作少而明确，每个动作都有声光或身体反馈。
- 数字人应放在山门或私密偏殿，主殿保持安静。
