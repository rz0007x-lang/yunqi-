# 云栖案例级场景执行计划

## 总原则

先把单人场景做成完整世界，再做角色与声音，最后接真实多人。每一批生成资产都必须先检查再进入下一批，避免一次花费大量生成额度后才发现风格不统一。

## 当前停点

单人完整场景、角色仪式、空间声音、浏览器降载和发布前检查均已完成。当前 `PresenceRoom` 只用 `BroadcastChannel` 支持同一浏览器不同标签页的本地状态演示，不属于真实多人。下一阶段应从房间服务、跨设备状态协议、权威座位仲裁、心跳重连与冲突恢复开始；详见 `pre-multiplayer-readiness.md`。

## 首批生成后的处理

1. 每个任务成功后立即下载 GLB 和 ZIP，避免临时下载地址过期。
2. 自动检查 GLB 结构、纹理数量、三角面数和包围盒。
3. 为每件资产生成本地旋转预览。
4. 按统一风格、轮廓完整性、可行走开口和比例给出通过或退回。
5. 只有通过验收的资产才把 manifest 状态改为 `accepted`。
6. 首批通过率达到门槛后，再建立第二批建筑连接件任务。

## 首批结果

- 通过：ARCH-003 侧殿、ARCH-004 直廊、ARCH-006 院墙、ARCH-009 静坐亭、ARCH-010 石桥。
- ARCH-004 首轮因一端封墙被拒绝；收紧模块化提示词后重生成通过。
- 5 件资产均需要落地归零；全部或部分需要尺度规范化与 LOD。
- 生成 ZIP 只作本地源交付，不进入 Git；正式 GLB 和逐件验收记录进入版本库。
